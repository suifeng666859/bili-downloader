# B站视频下载器

Windows 桌面端的 B 站视频下载工具，PySide6 图形界面，一次填地址、选清晰度就能拿到音画完整的 MP4。

> 起因是想跑通 [Henryhaohao/Bilibili_video_download](https://github.com/Henryhaohao/Bilibili_video_download)（Apache-2.0），
> 但那是 2019 年的项目：`interface.bilibili.com` 加密接口已返回 403，`imageio.plugins.ffmpeg.download()`
> 和 `moviepy.editor` 也被上游移除，且只认 av 号不支持 BV 号。
> 本项目是**按同样的目标重新实现**的现行版本，未复制其代码。感谢原作者提供的思路。

## 特性

- 支持 **BV 号 / av 号 / 完整链接 / b23.tv 短链**
- 支持 **分P**：链接带 `?p=2` 只下该集，不带则下全集
- 清晰度可选：360P / 480P / 720P / 1080P（1080P+ / 1080P60 / 4K 需登录或大会员，
  且**取决于片源是否提供该档** —— 不是每个视频都有）
- 日志会直接列出**该视频实际可用的清晰度与最高档**，不用猜上限在哪
- **扫码登录** —— 点一下按钮，用手机 B站 App 扫码即可拿到登录态（也可手动填 `SESSDATA`）
- 登录态持久化到用户目录，下次打开自动带上
- 走 **DASH** 取流，视频流与音频流分开下载后用 **ffmpeg `-c copy` 直接封装**，不重编码 —— 耗时就等于下载时间
- **同一清晰度自动挑码率最高的转码档**（见下方「为什么有的 1080P 反而更糊」）
- 实时速度与进度显示，支持中途停止，完成后自动打开文件夹
- 自动探测 ffmpeg（PATH / 程序同目录 / 常见安装位置）

## 环境要求

- Windows
- Python 3.9+
- ffmpeg（**必需**，用于音视频合流）

```bash
pip install -r requirements.txt
```

ffmpeg 三种装法任选：

1. 加入系统 PATH
2. 把 `ffmpeg.exe` 放到本程序同目录
3. `winget install Gyan.FFmpeg`

## 使用

```bash
python bilibili_video_downloader.py
```

在界面里填入视频地址 → 选清晰度 → 选保存目录 → 开始下载。

默认保存到 `C:\Users\<你>\Videos\bilibili\<视频标题>\`。

## 想下 1080P？先登录一下

B站对**未登录**的请求只发 480P，而且码率会被压到 200~300 kbps（实测某个视频只有 185 kbps），
所以看起来就是糊的。这是服务端限制，不是程序的问题。带上登录态才有 1080P / 1080P60 / 4K。

### 推荐：扫码登录

点程序里的 **「扫码登录」** 按钮 → 用**手机 B站 App**（右上角「+」→「扫一扫」）扫弹出的二维码 →
手机上点「确认登录」。凭据会自动填入并保存，之后打开程序就是登录态。

> 微信扫一扫不行，必须是 B站 App。二维码有效期约 3 分钟。
> 这条路走的是 B站官方 passport 接口，不用碰浏览器 Cookie。

### 备选：手动填 SESSDATA

1. 浏览器（Edge / Chrome）打开 bilibili.com，确认已登录
2. 按 `F12` → 顶部切到 **存储 / Storage**（旧版叫「应用程序 / Application」）
   → 左侧 **Cookies** → 展开 `https://www.bilibili.com`
3. 找到名为 **SESSDATA** 的那一行，双击「值」列，全选复制
4. 粘贴进程序的「登录 Cookie」框，重新下载即可

整条 Cookie 串（含 `SESSDATA=...; bili_jct=...`）也认。勾选「记住 Cookie」后会存到
`%USERPROFILE%\.bili_downloader.json`，下次自动填上；取消勾选即不再保存。

> SESSDATA 等同于你的登录凭证，只留在本机，不要发给别人或截图公开。
> 想让它失效，在 B站点「退出登录」即可。

## 为什么有的 1080P 反而更糊？

B站同一个清晰度会**并行提供三份独立转码**：`avc1`(H.264) / `hev1`(H.265) / `av01`(AV1)，
码率能差 3 倍。实测某个视频的 1080P：

| 编码 | 码率 |
|---|---|
| `avc1` | 1787 kbps |
| `av01` | 904 kbps |
| `hev1` | **589 kbps** |

不少工具（包括 B站官方 PC 客户端）默认取 HEVC 那档 —— 码率最低的一份，看着就发糊；
而网页播放器走的是 AVC / AV1，所以在线看更清楚。

**本项目默认在同一清晰度里取码率最高的那份**（一般就是 `avc1`），并在日志里列出全部候选：

```
画质：1080P 高清  1920x1080  avc1.640032  码率 1787 kbps
  同档可选编码：avc1 1787kbps  av01 904kbps  hev1 589kbps（已选最高）
```

### 档位上限由片源决定

**「1080P60」「1080P+」「4K」不是每个视频都有** —— B站只下发 UP 主实际上传过的档位，
选了没上传的档会自动回落到下一档。实测一个短视频 `accept_quality` 只有 `[80, 64, 32, 16]`，
**最高就是 1080P**，那么它的天花板就是 1080P 的 `avc1`（约 2277 kbps），谁都下不到更高。

程序会把该视频的可用档位打进日志，比如：

```
  该视频可用清晰度：1080P 高清 / 720P 高清 / 480P 清晰 / 360P 流畅（最高 1080P 高清）
```

所以想尽可能清晰：**片源有 1080P60 就选它**（同档 `avc1` 实测能到 2722 kbps，高于 1080P 的 1787），
没有就只能到 1080P。两种情况都认准 `avc1`。

### 为什么下载的仍不如在线播放锐？

1080P 的 `avc1` 也就 1800~2300 kbps，属于中等码率 —— B站下发的是**重压转码版**，
UP 主上传的原始文件平台不会对外提供（所有视频平台同理）。
另外 B站客户端与网页播放器带「画质增强」做实时锐化/超分，在线看会显得更锐；
下载得到的是未经处理的原始流。这属于平台侧的观感差异，不是下载画质有问题。

## 工作原理

1. `api.bilibili.com/x/web-interface/view` 取视频信息与 `cid`
2. `api.bilibili.com/x/player/playurl` 加 `fnval=4048` 取 **DASH** 流，拿到多档视频流和独立音频流
3. 分别下载后交给 ffmpeg `-c copy` 封装成 mp4

## 已知限制

- **1080P 及以上需要登录**。不带登录态时服务端最高只给 480P，且码率被压到 200~300 kbps（看着就是糊的），这是 B 站的服务端限制，不是代码问题。点「扫码登录」即可解决，见上方章节。
- **付费内容、会员专享、番剧** 无法下载，会明确报错。
- 请仅用于下载你有权保存的内容，遵守 B 站用户协议与著作权法。
